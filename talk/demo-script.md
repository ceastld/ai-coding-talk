# 现场走环（约 6 分钟）

不要再走工单分拣。只把两个环走一遍。黑板或幻灯片都行。

## 1. 内环：一条失败测试（3 分钟）

口头任务：

> 登录按钮文案错了。仓库里已经有一条红测试：点登录应看到「进入」，现在是「登陆」。

走法：

1. **Plan** — 改一处文案；成功标准是这条测试绿；不动登录逻辑。
2. **Implement** — 只改文案，产出 diff。
3. **Check** — 跑那条测试。红 → 回 Implement。绿 → 往下。
4. **Accept** — 测试绿了才 commit。不要先提交再「看起来对」。

如果改着改着想顺手重构登录：回 Plan，不要在 Implement 里扩 scope。
如果转了三圈还红：停，给人。

## 2. 外环：Issue 回到 PR（3 分钟）

口头任务：

> 用户开了 issue：登录按钮写成「登陆」。要的不是本地改完，是一条能审的 PR。

走法：

1. **Issue** — 有没有复现、期望、现在行为。缺了先问，不要直接写代码。
2. 信息够 → 开分支，进入内环。
3. 内环 Accept = 在分支上 commit，并 **开 PR**。
4. **CI** 再跑一轮 Check。红了回到内环，不要求人合。
5. **Merge** 是人按的。Agent 的活停在 PR。

收束一句：内环把代码做对，外环把仓库里的事送到可审查的出口。
