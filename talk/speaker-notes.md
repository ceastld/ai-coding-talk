# 讲解词

对着 14 页讲。每页大约 1 分钟。括号里可省。

## 开场

「今天不比模型。我想讲怎么设计 Agent Loop，让写代码能自动转起来。」

「核心就这一条：Plan，Implement，Check，过了才 Accept。另外一套是 Issue 回到 PR。」

## 范围

直接裁：不讲 prompt，不讲工单分拣，不讲产品功能。
「如果循环没设计清楚，后面那些都是装饰。」

## 问题

用手比：写了 → 看起来对 → 丢进仓库。
缺三样：计划、可判定的检查、进仓库的门。

## 内环

把四格画在空中，或指幻灯片上的箭头。
强调：Accept 之前仓库当没发生过。
Check 红了先回 Implement；发现计划错了才回 Plan。

## 四格

每一格只做一件事。
「Implement 不要顺便改需求。Check 不要自己动手改代码。否则你分不清是实现错了，还是目标变了。」

## Check

「环能不能转，取决于 Check 是不是命令。」
举一个就够：`pytest` 红了就回改，绿了才往下。
「模型说『应该对了』不算过。」
补一句预算：转三圈还红，停。

## 失败分流

三路：再改 / 重画计划 / 停给人。
「这三路不写死，Agent 会空转，或者偷偷改需求。」

## Accept

「前面都是草稿。唯一进仓库的口是 Accept。」
合主线、对外口径、破坏性改动，人按。

## 外环

「本地做对还不够。仓库里的事，从 Issue 进，从 PR 出。」
指：信息不够先停；够了才进内环；Agent 停在开 PR；CI 再 Check；合是人。

## 对照

内环管代码对不对。
外环管这件事在仓库流程里走完没有。
「开了 PR 只是外环的 Accept，不是做完了。」

## 四问

设计任何自动化写代码，先问这四句。
「先画图，再写 skill，再写 prompt。顺序反了就会变成几十页空话。」

## 反模式

快速念。用来对照听众自己的流程。
停一下问：「你们现在哪一条是真的？」

## 收尾

念三句。问：「你们的写代码 Agent，哪一格是空的？」
