AI 编程怎么真正跑起来

不是多开几个聊天窗口。
是 人写规则，Agent 按规则干活。

开场

今天不讲这些

  • 哪个模型最强
  • Prompt 怎么写才「聪明」
  • 替你生成一个完整产品

讲流程：事情怎么进来、谁做、做到哪停、怎么复查。

开场

聊天写代码，撑不久

  • 上下文会漂 — 同一个 bug 换窗口，规则重讲一遍
  • 边界在人脑子里 — 「这个别自动关」只存在于某次对话
  • 做完没法关单 — 没有已处理 / 未处理，只会永远「请再验证」
四层

从人到系统

  1. 对话 — 这一次，把一件事做完
  2. Skill — 一种情况，一种做法
  3. Automation — 规则仓库。改文件，行为跟着变
  4. 产品也是 Agent — 动作、MCP，别人也能接进来
第一层 · 对话

一次对话只办一件事

同一条 PR、同一个 bug，留在同一个会话。

目标变了就新开，第一条消息带锚点：PR 号、分支、约束。

不要让一个窗口同时改 CI、迁面板、讲跨平台。

第一层 · 对话

交给 Agent 的方式

把 问题和成功标准 交给它。

不要把「根因在第 N 行，改成 Y」写死。猜的标成假设。

人只在不可逆的地方拍板：合并、对外口径、破坏性改动。

第二层 · Skill

一种情况，一种做法

---
name: inbox-triage
description: 新反馈还没分类时：先点名已处理 / 未处理，再打标。
---
# 步骤
1. 先点名已处理或未处理
2. …

写清：何时用、自动做什么、何时停。写意图，不要写会死的工具参数。

第二层 · Skill

真的长这样

issue-triage

新 issue，或还没分拣

need-more-info

缺复现 / 版本 / 期望

already-fixed

当前代码已经没了 → 关单

try-auto-fix

带了 TryAutoFix，才允许开修

来源：qk-automation。规则覆盖的直接做。

第三层 · Automation

规则放仓库

Agent 先读规则，再读匹配的 skill，再动手。改 markdown，不用再跟它嗨。

mode: notify-only    # 只报，不动
mode: apply-skills   # 按表真正动手

监控可以一直跑。动手必须有开关。

第三层 · Automation

动手之前先点名

已处理 / 未处理。 这是第一句话。

看时间线、关联 PR、维护者备注、当前主线。不要只看用户正文。

已经没了 → 关 issue。不要用「请再验证」收尾。

第三层 · Automation

能自动 vs 必须停

自动（不必问）

  • 能看清的 bug / 需求 → 打标
  • 缺信息 → 三问
  • 已处理 → 关单
  • 带 TryAutoFix 且改法局部 → 开修

必须停

  • 要不要做这个需求
  • wontfix / 承诺版本号
  • 数据格式、密钥、花钱
  • 只为这一个关键词打补丁
第三层 · Automation

升级也要带球

  1. 已经做了什么（先点名已处理还是未处理）
  2. 建议怎么走：修 / 不修 / 等复现
  3. 反对时回哪一个词：「不修」「等下版」

禁止只写：「先不改，等你定。」

第四层

产品自己也是 Agent

  • quicker_eval — 跑 Host JS，不挂 chrome
  • actions.search / export / validate / import
  • 写操作要开门；破坏性 API 即使开了门也拦

本机 loopback + Bearer。默认关。测试可以在 Linux 上跑。

第三幕 · 现场走单

三张假工单，当场走决策

单 A

先看时间线，再开口

截图贴图会把窗口卡死

2.x 里贴图之后鼠标动不了。相关开发 PR 已合进主线。当前已经没了。

① 查时间线、关联 PR、当前主线

② 第一句点名：已处理

③ 关单。评论：当前已经是这样了。

命中 already-done

证据够了就关。不要「请再验证」。

单 B

看不清就先问

动作运行很慢

有时候会卡一下。没有版本、没有复现、没有期望。

① 点名：未处理

② 看不清类型 → need-more-info

③ 三问：版本、怎么复现、期望怎样

不要猜补丁

缺这三样就不要分拣，更不要开修。

单 C

能看清也不等于开修

面板搜索清空后选中项丢了

打开面板 → 搜「截图」→ 清空搜索框，原来高亮没了。当前预览。

① 点名：未处理

② inbox-triage 打 bug

③ 停在摘要。没有 TryAutoFix，不开修

开修的钥匙不在聊天里

在标签和规则表。能看懂只说明能分拣。

第四幕 · 动作

人是按钮，Skill 是做法

动作 A · 扔给分拣

选中一段反馈 + 热键。出口：建议标签 + 一句人话。默认不改线上 issue。

动作 B · 会前一页纸

按 meeting-brief 生成一页能念的提纲。只写给自己，没有写进别人仓库的负担。

聊天窗口不再是唯一入口。

第五幕 · 真事

审查机器人不是合并闸

自动审查会看旧文档，把合法字段打成错误。也会抓到真的数据丢失。

瞥一眼，不当自动闸。合之前人看合同，不看语气。

第五幕 · 真事

损坏的信封不能当正文写盘

write_file 的 payload 以 @@ 开头但头是坏的。当原文写就会覆盖目标文件。

看起来像信封就 拒绝，清掉半成品正文。自动层越能干，拒绝路径越要干净。

第五幕 · 真事

Agent 契约要能离开 Windows

鉴权、eval、写门禁、导入导出如果只能在 Windows testhost 里跑，云端就测不了。

把 live 装配和可测核心拆开。dotnet test 在 Linux 过了，再合进主线。

带走

三句话

  1. 一种情况，一个 Skill。写清何时停。
  2. 规则放仓库。改文件，不要改聊天记录。
  3. 先点名已处理 / 未处理。已经没了就关，不要请人再验证。
